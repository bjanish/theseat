The Seat — Build Checklist

Spec order = build order. Each section done-done before moving to the next.

1. Tech Stack & File Structure

  • SwiftUI + Network framework + AVFoundation
  • @MainActor @Observable SessionManager
  • SeatMessage in separate file
  • #if DEBUG for all test infrastructure
  • Bundle ID: com.bjanish.askme
  • App icon: ornate chair, dark background, gold tone, spotlight

2. Networking

  • NWBrowser + NWListener + NWConnection, includePeerToPeer = true
  • Service type: _theseat._tcp
  • Service name: playerName-deviceID-host or playerName-deviceID
  • 6-char UUID device ID in UserDefaults
  • Self-filter, endpoint dedup, device ID dedup
  • Connection timeout (3s), circuit breaker (3 attempts)
  • Host starts listener, accepts connections
  • Player browser finds -host service, auto-connects, sends .join
  • Same-name auto-suffix ("Brian 2")
  • Connection-to-name dictionary (not parallel arrays)
  • Messages: join, question, currentQuestion, passTheSeat, youAreHost, newHost, sessionEnd, heartbeat
  • Toast system for connection events
  • Browser runs passively on solo screen, shows host name on Join button
  • Ghost connection timeout (3s — no .join received)
  • Test host-to-player on two real phones (second session reconnect)
  • Verify auto-reconnect after player resume from background

3. Screens & UI Skeleton

  • Name entry: text field, persists UserDefaults, first launch only
  • Solo: seat glow + "THE SEAT" branding + Host/Join buttons
  • Solo: spotlight effect, Cinzel font, tagline on appear
  • Solo: "Join [host name]'s Session" button with gold glow when host detected
  • Host: card stack with gold border, Cinzel font, swipe left/right to cycle, tap to choose
  • Host: flourish decorations above and below cards
  • Host: "swipe to browse · tap to choose" instruction
  • Host: full-screen question display in Cinzel, tap to dismiss
  • Host: Pass button, End button in top bar
  • Player: text input with gold underline, 150-char counter, send button
  • Player: "Your question is in" + "Stay connected" after sending
  • Player: shared question display (Cinzel) when host selects a question
  • Player: Leave button
  • Settings accessible from solo screen

4. Host Queue Behavior

  • FIFO array
  • Swipe left/right = cycle through questions (nothing deleted)
  • Tap = select (full-screen, sent as .currentQuestion)
  • Queue persists during session
  • No duplicate detection on question text
  • Host session stays live after last player leaves (host ends manually)

5. Player Input & Character Limit

  • 150 characters max
  • Counter shows remaining
  • Enforced client-side (stops accepting at 150)
  • Send disabled when empty
  • Light haptic on send
  • Field clears after send
  • ONE question per HOST — input locks after sending, resets on seat pass
  • After send: show "Your question is in" + "Stay connected" confirmation
  • Confirmation modal before sending — player reviews question before committing
  • Trim + reject empty whitespace

6. Visual Design

  • Dark UI: Color(white: 0.08) background with spotlight gradient
  • "THE SEAT" Cinzel font, tracked uppercase, gold tone, text shadow
  • Chair image with floor shadow, easter egg gold glow on tap
  • Full-screen question: Cinzel font, centered, tap to dismiss
  • "The Seat" watermark during full-screen display
  • Card stack with gold border, peek to the right
  • Flourish decorations (ornamental gold image) above and below cards
  • Gold glow on "Join" button when host detected
  • Player screen polish: minimal, input is focus

7. Audio & Haptics

  • Question received (host): ping + light haptic
  • Question sent (player): light haptic
  • Pass the Seat: medium haptic both sides
  • Player connects: connection sound + medium haptic
  • Question selected: light haptic
  • Audio session: .playback + .mixWithOthers
  • Custom ping sound bundled (not card flip)
  • Easter egg: heavy haptic on chair tap

8. Pass the Seat

  • Host taps "Pass" → player list sheet
  • Tap name → .passTheSeat + .youAreHost sent
  • Target becomes host, original becomes player
  • Queue does NOT transfer (fresh start)
  • Connections stay alive
  • .newHost(name:) broadcast to all players
  • Player input resets on new host (hostRound counter)
  • Toast: "[Name] is in the seat" on seat pass
  • Medium haptic both sides
  • Test pass on real devices

9. Lifecycle

  • Host backgrounds → .sessionEnd → teardown
  • Player backgrounds → cancel connection + browser
  • Player resumes → restart browser, auto-reconnect
  • Host resumes → session gone, back to solo
  • "End Session" = same as backgrounding
  • Player returns to solo on host disconnect
  • Idle timer disabled while active
  • Test background/resume on real devices

10. Onboarding

  • 3 slides: hero, flow, control
  • TabView swipe pattern
  • Local network permission mention
  • Polish slide content and visuals

11. Paywall

  • Ship v1.0 free — no paywall code needed

13. Solo Mode: Would You Answer?

  • Random questions from curated pool
  • Swipe right = "I'd answer that" → streak increments
  • Swipe left = "Pass" → streak resets to 0
  • Streak counter + best streak
  • Question pool (100+ questions)
  • Tap chair to start

12. Open Questions (decisions made)

  • No going back to previous questions — swipe cycles, nothing deleted
  • Players see current question (shared screen moment)
  • Host does NOT see who asked (full anonymity)
  • Empty queue: glow + "Waiting for questions..."
  • One question per host (not unlimited)

Debug: Simulated Characters

  • Each sends one random question (staggered 2s/4s/6s)
  • Valid targets for "Pass the Seat"
  • Question pool: PG-13 funny/awkward questions
  • Production/Release builds: no simulated characters (behind #if DEBUG)
